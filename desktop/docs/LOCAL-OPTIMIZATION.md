# 单机使用优化：活索引 + 存储清理

定位是**单机日常使用**，所以这轮不做分发相关的事（Authenticode 已按你的定位搁置），只优化本机上真正会碰到的两个点。

## 一、索引现在是"活的"（原来要手点重建）

之前索引是快照：新任务不进去，必须点「重建索引」。现在改成了**跟随记录自动同步**：

| 环节 | 做法 |
|---|---|
| 写入镜像 | 挂在 `Manager::update` —— 任务记录**唯一的写入收口点**（含节流保存），记录一变就标记脏 |
| 归档同步 | `archive` 直接同步（改的是 `archivedAt`，归档筛选必须跟着变） |
| 查询前落盘 | 列表查询先 `flush_index()`：界面每次取任务列表（约 800ms 一轮）都会把脏任务写进索引 |
| 启动自愈 | `attach_index` 时**全量对齐**一次，顺手清理记录已消失的孤儿 |

效果：**启动后索引立刻可用，任务结束后检索随即可见，不需要再点重建**。手工的「重建索引 / 对齐索引」保留为修复手段。

## 二、存储用量与安全清理

新增「存储」分区，四行互不重叠的用量（合计不重复计数）：

| 行 | 内容 | 可操作 |
|---|---|---|
| 任务记录与会话 | 记录根目录（**已扣除**隔离工作树） | — |
| 隔离工作树 | `worktrees/` | 在任务详情里逐个移除（分支保留） |
| 更新缓存 | `updates/` | **清理**（下次检查更新会重新下载） |
| 本地索引 | 索引库 + WAL/SHM | **重建**（清空后从记录重建） |

**一个刻意的安全决定**：索引**不做文件删除**。删除正在使用中的 SQLite 文件会让连接指向已删除的 inode，写入行为不可预期；所以索引走「清空 + 重建」，并且有一条测试断言 `index` **不是**文件清理目标。

## 三、过程中撞到的一条真实不变量

我给活索引写的第一个测试**失败了**，原因很值得记：任务记录加载器要求 **id 是合法 UUID 且文件名必须等于 id**（`Uuid::parse_str(&task.id)` + 文件名词干比对），否则整条记录被丢弃并记入警告。我的夹具用了 `task-1.json`，正好违反这条——把夹具换成真 UUID 后通过。

顺带确认了另一个行为：加载时若任务状态还是"进行中"，会被自动标成 `interrupted` 并写入说明（应用上次退出时任务没结束），这是既有设计，我这次没有改动它。

## 四、验证

```powershell
Set-Location desktop
npm test            # JS：96 项
npm run test:rust   # Rust：lib 82 项（新增 6 项：5 项存储 + 1 项活索引）+ 集成测试
cargo clippy --all-targets --features test-fixture -- -D warnings   # clean
npm run test:ui     # 真实 WebView2：33 项全过、渲染错误 0（新增存储面板断言）
```

新增的活索引测试走的是**真实加载路径**：造一条历史记录文件 → `Manager::new` 加载 → `attach_index` 对齐 → 断言索引立即有数据 → 改状态 → `flush_index` → 断言索引跟着变。

## 五、已知限制

1. **索引只覆盖子代理任务的记录**（元数据 + 输出片段），聊天消息与会话正文不在索引里；
2. **同步时机绑定列表轮询**：如果没有任何界面在取任务列表，写入会等到下一次轮询（有上界，不是无限延迟）；
3. **没有保留策略**：存储面板只显示与手动清理，没有"归档超过 N 天自动清理"这类规则；
4. **没有文件级下钻与 FTS 全文检索**：目前是 `LIKE` 子串匹配，中文没有分词与相关性排序；
5. 隔离工作树仍然只能逐个移除（没有一键清理孤儿工作树的入口，避免误删在用目录）。
