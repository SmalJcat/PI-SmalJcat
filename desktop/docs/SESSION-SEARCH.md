# 会话全文检索（FTS5 trigram）

单机使用最缺的能力：**找到几周前聊过的内容**。原来的侧栏搜索只在标题和工作区路径上做子串匹配，现在正文也能搜。

## 一、实现要点

| 点 | 做法 |
|---|---|
| 存储 | FTS5 虚拟表 `sessions_fts(path, title, body)` + `session_files(path, mtime, size, indexed_at, chars)` 记录增量状态 |
| 分词 | `tokenize='trigram'` —— 对中文这种无空格语言可以做**子串匹配**，并自带相关性排序 |
| 短词回退 | trigram 需要 ≥3 个字符；更短的查询回退 `LIKE`，并在界面上说明"按包含匹配"，**不静默返回空** |
| 排序 | `bm25(sessions_fts, 0, 4.0, 1.0)`：标题权重高于正文 |
| 片段 | `snippet(..., '…', 16)` 给出命中处上下文，界面显示两行 |
| 增量 | 按（路径, mtime, size）判断是否需要重建；未变动跳过 |
| 清理 | 文件被删除后同步删除索引行（否则会搜到已不存在的会话） |
| 容错 | 会话是 JSONL；**单行损坏只跳过该行**，不让整个文件失去检索价值 |
| 体积 | 单文件读 8 MiB、入库正文 256 KB 上限；遍历深度 6 层 |
| 惰性建索引 | 第一次检索时若索引为空，先建一次再搜，并把结果如实告诉用户 |

索引文件是独立的 `sessions.sqlite`（与会话文件分开放）。启动时后台同步一次，不阻塞首屏。

## 二、界面

侧栏搜索框输入 ≥2 个字符时，标题匹配之外多出「内容匹配」区块：显示会话标题 + 命中片段，点击即打开该会话。区块内提供「刷新索引」，完成后会报告 `N 个会话（新索引 x，跳过 y，失败 z）`。

**第一次做的时候这里是个坑**：我在界面上把同步错误 `.catch(() => {})` 吞掉了——界面看起来正常，但什么都搜不到，也看不到原因。现在错误会直接显示在面板里，这条也写进了教训。

## 三、端到端验收抓到的真 bug

单元测试全绿、构建通过，但验收里点「刷新索引」后**一个命中都没有**。原因是我把收集器的扩展名过滤写成了 `.json`，而 **Pi 写的会话文件是 `.jsonl`** —— 索引永远是空的。

我直接从 `%TEMP%` 里翻出一个真实会话文件核对：首行是 `{\"type\":\"session\",\"version\":3,...}`，其后每行一条消息，扩展名 `.jsonl`。修掉之后一切正常。

**教训**：单元测试的夹具扩展名必须与真实产物一致——我的夹具也写了 `.json`，所以测试恰好绕过了这个 bug。现在有一条专门的断言 `session_file_detection_covers_both_extensions` 守着两种扩展名。

## 五、已知限制

1. **索引不监听文件变化**：会话在本次运行中继续追加内容时，索引要等下一次启动同步或手点刷新（未来可加文件监听或在会话结束时增量更新）；
2. **只索引文本消息**（user/assistant 的文本），思考块、工具参数与工具输出不入索引；
3. **不支持多关键词布尔检索**（`AND/OR/NEAR` 语法没有暴露给界面），短语匹配是精确子串；
4. **没有按会话/时间过滤**，也没有"跳转到命中位置"（点开是会话开头，不会滚动到命中处）；
5. `session-search` 每次查询都会尝试惰性建索引判断（只读一次计数），开销可忽略，但没有做成"后台预热 + 状态提示"的完整形态。
