# 可自定义快捷键

从 ChatGPT 设置的快捷键页移植过来的能力，但**不只是加了一页设置**——原先写死的全局按键处理改成按绑定表派发，并顺带补上了它设置里默认就有的三个动作。

## 一、动作与默认键

| 动作 | 默认键 | 生效范围 | 行为 |
|---|---|---|---|
| 新会话 | `Ctrl+N` | 全局 | 重建会话 |
| 打开文件夹 | `Ctrl+O` | 全局 | 切换工作区 |
| 设置与连接 | `Ctrl+,` | 全局 | 打开设置 |
| 停止任务 | `Esc` | 运行中 | 中断当前任务（仅运行时有反应） |
| 搜索会话 | `Ctrl+K` | 全局 | **聚焦侧栏搜索框并全选**（新增能力） |
| 切换左栏 | `Ctrl+B` | 全局 | **显隐左侧栏**（新增能力） |
| 切换右栏 | `Ctrl+Shift+B` | 全局 | **显隐文件/改动面板**（新增能力） |

## 二、组合键规则（`src/shortcuts.mjs`，纯函数）

1. **归一化**：修饰键顺序固定为 `Ctrl+Shift+Alt`，字母统一大写；`Meta`（Cmd）并入 `Ctrl`，避免 Windows/macOS 两套写法；
2. **单按修饰键不成组合**：只按 Ctrl/Shift/Alt/CapsLock 不会产生绑定；
3. **存储大小写无关**：`shift+ctrl+k` 与 `Ctrl+Shift+K` 等价（查表用小写索引）；
4. **逐项回落**：某个动作的组合键非法时只回落该动作的默认值，其它自定义保留；未知动作直接丢弃；
5. **冲突检测**：赋值时若组合键已被别的动作占用，**拒绝并说明占用者**（"该组合键已被「搜索会话」占用"），不静默覆盖；
6. **命中即完全相等**：`Ctrl+K` 与 `Ctrl+Shift+K` 互不触发。

## 三、录制交互

点「录制」后进入捕获状态，监听挂在 **document 的捕获阶段**：

- 按钮失焦也不会丢键；
- **先于应用的全局快捷键处理**，所以录制时按 Ctrl+N 不会真的新建会话；
- `Esc` 取消录制；只按修饰键不结束录制；
- 成功写入后立即显示新组合键；失败（冲突/非法）显示原因并保持录制状态；
- 分区顶部会在存在重复绑定时给出提示（例如手工改存储造成的冲突）。

## 四、端到端断言（不只是"控件存在"）

验收里加了完整链路，四步都断言：

```js
assert.equal(await page.locator('.pref-row').count(), 7);          // 7 个动作
await 录制「切换左栏」→ 按 Ctrl+J;
assert.equal(kbd 文本, 'Ctrl+J');                                   // 录制真的改写绑定
await 关闭设置; await page.keyboard.press('Control+J');
assert.notEqual(.sidebar 可见性, 关闭前);                            // 自定义键真的生效
await 再按一次 → 可见性切回;
await 重开设置 → 恢复默认快捷键 → kbd 文本等于 'Ctrl+B';              // 恢复默认真的写回
```

验收项 **31 → 32**，全过。

## 六、已知限制（诚实清单）

1. **`Esc` 无法被改绑**：录制时 Esc 是"取消"，因此不能把别的动作绑到 Esc（Esc 仍可保留为「停止任务」的默认值）；要支持需引入"点击录制后再按 Esc 需二次确认"的交互；
2. **只支持单段组合键**：不支持 VSCode 那种 `Ctrl+K Ctrl+S` 两段式序列；
3. **作用域只有"全局"与"运行中"**：没有按窗口/面板细分，也没有鼠标侧键与手势；
4. **冲突时按动作表顺序命中**：允许手工改存储造出重复绑定（UI 会警告，但不阻止），此时靠前的动作先命中；
5. **快捷键提示文案未全部联动**：侧栏「Ctrl N」「Ctrl ,」等标签仍是写死的（输入框底部的 Enter 提示已联动）。
