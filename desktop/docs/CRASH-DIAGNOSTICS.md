# 崩溃与异常退出诊断（纯本地）

单机用最实际的需求：**出问题能查到原因**。这轮把 P0 里最后一项补上——不做联网上报，诊断信息就放在用户自己的数据目录里。

## 一、三件事

| 能力 | 落点 |
|---|---|
| Rust panic → 本地报告 | `panic::set_hook`：写版本 / 线程 / 位置 / 消息 / **回溯** |
| 正常退出标记 | 退出前写 `<数据目录>/last-exit.json`；下次启动据此区分「异常退出」 |
| 前端错误 → 本地报告 | `window.onerror` + `unhandledrejection` 上报到同一目录（不影响控制台行为，只多一份副本） |

界面在「设置 → 连接」里加了一块**崩溃诊断**：上次退出状态、崩溃份数、前端错误条数、报告目录、清空按钮、最近三条报告预览。

## 二、一个实现时发现的设计问题：前端错误不能算崩溃

最初我把前端错误也写成 `crash-*.txt`，那样**一个 JS 报错会让下次启动显示「上次异常退出」**——语义就错了。改成按前缀区分：

| 前缀 | 含义 | 是否参与「异常退出」判定 |
|---|---|---|
| `crash-` | Rust panic | **是** |
| `renderer-` | 前端脚本错误 | 否（单独计数展示） |

裁剪也按前缀各自进行（各留最近 20 份），避免前端错误把 panic 报告挤掉。

判定规则：存在比正常退出标记**更新**的 `crash-` 报告 → 异常退出；没有标记也没有崩溃报告 → 视为干净。

**刻意的取舍**：进程被强杀（既没有标记也没有崩溃报告）会被判为「干净」。强杀不是崩溃，我们不为它报警——判定只针对真正的 panic。

## 三、验证

```powershell
Set-Location desktop
npm test            # JS：96 项
npm run test:rust   # Rust：lib 105 项（诊断 6 项）+ 集成测试
cargo clippy --all-targets --features test-fixture -- -D warnings   # clean
cargo fmt --check   # clean
npm run test:ui     # 真实 WebView2：41 项全过、渲染错误 0
```

单元测试覆盖：报告文本要素（含「无回溯时不出现回溯段」）、按前缀裁剪到 20 份、异常退出判定（无标记有崩溃 → 异常；崩溃早于标记 → 干净；标记后又有崩溃 → 异常）、**前端错误不算崩溃**、清空幂等、标记读写。

验收里两条：

| 验收项 | 断言 |
|---|---|
| 崩溃诊断：上次退出干净、崩溃 0 份、前端错误 N 条 | 全新环境 `cleanExit === true`、`crashCount === 0`、报告目录含 `crashes`、界面显示上次退出状态 |
| 崩溃诊断：正常退出标记已落盘 | **应用关闭后**读取 `<数据目录>/last-exit.json`，断言 `clean === true` 且带时间戳 |

## 四、调查过程（一条值得记的教训）

写完标记逻辑后，我在验收的临时目录里**找不到** `last-exit.json`，一度怀疑写入失败。逐个排查发现：

1. 验收脚本在收尾时 **`rm -rf` 掉了自己的临时 profile 目录**——标记是随应用退出写的，随后就被一起删了；
2. 残留的那些目录全部来自**中途失败/被杀的运行**，那里没有标记恰恰是**正确行为**。

于是我把断言挪到**清理步骤之前**（关闭应用之后、`finally` 删目录之前），这才拿到真实证据：标记确实写在了 `<profile>/last-exit.json`。

**教训：证据可能被收尾清理步骤删掉——断言要放在清理之前。**

## 五、已知限制

1. **setup 之前的 panic 抓不到**：钩子在 `setup()` 里安装，更早的崩溃（例如插件初始化阶段）不会留下报告；
2. **release 构建会剥符号**：`Cargo.toml` 的 `[profile.release]` 里有 `strip = true`，因此发布版里的回溯会很单薄。要可读的回溯需要改 `debug = 1` / `strip = "none"`，代价是体积变大——这个取舍留给以后决定；
3. **只覆盖主进程**：WebView2 的**渲染进程崩溃**由 Chromium 自己处理，不在本钩子里；前端**脚本错误**已覆盖；
4. **强杀不算异常**（见上的取舍），因此它不会出现在诊断里；
5. **没有去重/聚合**：同一处 panic 反复发生会留下多份报告（按时间裁剪保 20 份）；报告是纯文本，没有自动上报与云端聚合（刻意不做）。
